## 一、前测 / 后测（识别率提升）

### 需要几个人

**最少 10 人，建议 15 人。** 少于 10 人做配对检验没有说服力，评委问起来站不住。

找同学时注意：**没接触过本项目剧本和题库的人**。如果被测者提前看过题，前测就失效了。

### 一次测试的流程（每人约 15–20 分钟）

```
① 打开 quiz.html，填编号（P01/P02…），选「前测」，答 20 题      ≈5 分钟
                 ↓
② 打开 demo/index.html，选一个剧本，真打一场，看复盘评分卡      ≈5–8 分钟
   （建议统一用「冒充公检法」，保证所有人训练内容一致）
                 ↓
③ 回到 quiz.html，同一编号，选「后测」，答同一套 20 题          ≈5 分钟
```

**② 为什么必须真打一场**：只做题不做对抗，测出来的是"题目记忆"不是"训练效果"。必须让被测者真的和骗子 Agent 对话一轮。

### 编号规则

- 用 `P01`、`P02`… 这样的序号，**不要写真实姓名**
- 同一个人的前测和后测必须用**同一个编号**，否则脚本配不上对

### 收集数据

`quiz.html` 把记录存在浏览器本地（`localStorage`），不上传任何数据。

- 单台电脑跑完所有人 → 点「导出全部记录」→ 得到 `前测后测_全部_N条.csv`
- 多人多台电脑 → 每人点「导出本次结果」→ 把多个 CSV 一起交给负责人

### 分析

```bash
python 评测/analyze.py 前测后测_全部_15条.csv
```

输出：

- 控制台：前测均值、后测均值、**提升百分点**、配对 t 检验 p 值
- `评测/结果/前测后测对比.png`：左图前后对比、右图每人的变化连线
- `评测/结果/分析报告.md`：可直接粘进材料的结论

**写进材料时怎么说**：

> 招募 15 名未接触过本项目的在校学生，训练前后用同一套 20 题测验。
> 前测平均识别率 42%，后测 78%，提升 36 个百分点（配对 t 检验 p < 0.001）。

数字必须来自实际跑出来的结果，**不要套用上面这个示例**。

## 二、破绽标注召回率

> ⚠️ 这一项依赖平台上的复盘 Agent，**AgentArts 开通前做不了**。脚手架已备好。

### 为什么要人工标注

"召回率 ≥85%" 的意思是：人眼能看出的破绽，复盘 Agent 也要能看出 85% 以上。
所以要有一份**人工标注的标准答案**，再拿 Agent 的输出和它比。

### 流程

1. 收集 **50 条**真实对抗对话（用 Demo 或平台跑，导出对话记录）
2. 人工逐条标注：这段对话里**应该**被识别出哪些红旗
3. 跑复盘 Agent，拿到它实际标注的结果
4. 用脚本算召回率 = 命中的红旗数 / 应标注的红旗总数

### 标注模板

见 [标注模板.csv](标注模板.csv)，字段说明：

| 字段 | 含义 |
|------|------|
| `对话ID` | D01–D50 |
| `轮次` | 第几轮 |
| `原文` | 骗子说的原话片段 |
| `应标红旗` | 人工判断这里应命中的高危触发点，多个用 `\|` 分隔 |
| `备注` | 存疑时写理由 |

### 计算

```bash
python 评测/recall.py 人工标注.csv Agent输出.json
```

（脚本在平台开通后按实际输出格式对接，接口已预留）

## 三、常见问题

**Q：能不能直接用脚本生成一批数据？**
不能。这是参赛材料，规则写明「材料效果与复现不符 → 取消晋级/获奖资格」。编造数据比没有数据更危险。

**Q：人数凑不够 10 个怎么办？**
做 6–8 人也行，但报告里要**如实写样本量**，并说明是初步结果。千万别写"15 人"却只有 8 份数据。

**Q：前测做好了但还没训练，能先放着吗？**
可以。每人做完前测后编号要记下来，训练完再补后测。`quiz.html` 会按编号+阶段覆盖，不会重复。

**Q：题目会不会泄露影响后测？**
前测故意不显示答案（`quiz.html` 已做），后测才显示错题解析。所以前测做完不能把解析给被测者看。
